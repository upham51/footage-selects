PHASE 1: THE BASE APP
A free, cross-platform desktop app that pulls selects from raw footage using only classical math: no machine learning, no network, fully offline. Target user: a videographer with about two hours of footage across roughly 170 clips (mixed formats, resolutions, frame rates, some proxies) who wants selects in a couple of minutes, then imports them into DaVinci Resolve, Premiere Pro, or Final Cut Pro. Stack: Tauri or Electron, whichever bundles ffmpeg and ffprobe more simply, with the per-frame math in native code. Targets: macOS on Apple silicon and Windows. Include the framework's auto updater using GitHub releases.
1. Drag in a folder or files. Probe every clip. Handle mixed frame rates, resolutions, variable frame rate, rotated clips, and clips with no audio. Analyze several clips in parallel with a progress bar and time estimate. Aim for roughly 50 times real time or better on an Apple M-series chip: decode at the sample rate only, downscale to about 480 pixels wide grayscale, use hardware decode where available.
2. Sample at a configurable rate, default 4 frames per second. Score focus (variance of the Laplacian), exposure (histogram based: penalize clipped highlights, crushed shadows, flat contrast), and motion stability (frame differencing or optical flow, separating smooth camera movement from shake).
3. Cache per-frame scores in a project file so the user can save, close, reopen, and never re-analyze. Only changing the sample rate needs re-analysis.
4. Selection step, separate from analysis and instant to re-run: smooth scores over time, apply adjustable thresholds for each score, build segments with adjustable minimum and maximum length, cap segments per clip, keep the best. Sliders update the selects live. Show selects while analysis is still running.
5. Clip detail view with per-frame score graphs and kept and dropped segments marked, so the user sees why.
6. Export Final Cut Pro XML (must import into DaVinci Resolve, Premiere Pro, and Final Cut Pro), an edit decision list (CMX3600), and a CSV. Selects go on video track 2 with color-coded markers whose notes contain the three scores. Handle 23.976, 24, 25, 29.97, 30, and 59.94 frames per second including drop frame. Timeline frame rate defaults to the most common in the footage and is selectable.
7. Summary line: footage in, selects out, clips analyzed.
Tests: generate synthetic clips with ffmpeg (sharp versus blurred, well exposed versus dark versus blown out, steady versus shaky) and assert the scores rank correctly, the selection returns expected segments, exports have correct timecode math, track placement, and markers, and projects save and reload. You cannot test imports inside the editors from here, so validate the XML against its published structure as far as you can and say plainly what is unverified.
Packaging: a GitHub Actions workflow that on a tag starting with v builds installers for macOS (Apple silicon) and Windows and attaches them to the release. The README explains in plain steps how to approve the unsigned Mac app on first open and how to get past the Windows SmartScreen warning. Order of work, committing at each step: analysis engine and tests, selection and project file, interface, exports, packaging. Tag v0.1.0.

PHASE 3: THE SMART PASS (optional, runs only on segments the classical pass already selected)
1. Near-duplicate suppression: one image embedding per candidate segment (keyframes at start, middle, end) using SigLIP 2 locally through ONNX Runtime, base size first, benchmarked on Apple silicon and Windows CPU. Check its license for commercial use and fall back to Nomic Embed Vision v1.5 if unsuitable. Cluster by cosine similarity with an adjustable threshold, keep the best per cluster, and mark the rest "duplicate of X" so one click restores them.
2. Speech awareness: local transcription with NVIDIA Parakeet TDT 0.6B v3 through sherpa-onnx, with Whisper turbo through whisper.cpp as fallback. Confirm word-level timestamps work before relying on them and use Whisper if Parakeet cannot provide them. Snap segment boundaries to the nearest sentence or silence within a tolerance, with a "protect speech" toggle and transcripts in the detail view.
3. Shot labels and search: label each segment with shot type (aerial, wide establishing, medium, detail, handheld, smooth tracking) and a short subject description using the same embeddings, add a plain-language search box that highlights matching segments, and write labels into marker notes.
4. Story order: an "arrange" mode that reorders selects into a simple arc using the labels, with timecode order one click away. Never reorder unless the user chooses arrange mode.
5. Optional cloud descriptions and taste score, off by default: Claude Haiku 5.5 (API model ID claude-haiku-5-5), with a setting for Sonnet 5.5 (claude-sonnet-5-5). The user pastes their own key into a settings field, stored in the operating system keychain and never in the project file, logs, or exports. Send at most 3 keyframes per segment, downscaled to about 768 pixels wide. Keep each request under 100,000 tokens because Haiku 5.5 charges five times more above that. Use prompt caching for the fixed instructions. Ask for strict JSON (shot_type, subjects, mood, usable_as, flaws, keeper score 1 to 10, one line reason), validate it, retry once, and cache by frame hash. Before running, show segment count, estimated cost, and a hard spend cap the user sets, and refuse to exceed it. Store per-million-token prices in one config file (Haiku 5.5 is $0.10 input and $0.50 output as of October 2026; verify against Anthropic's current pricing page).
6. Score blending: weighted blend of the three classical scores and the AI score with a slider each. The AI score moves a segment within a bounded range and cannot rescue footage that badly failed the classical thresholds unless a "creative override" toggle is on.
7. A "check my taste" screen: the user thumbs-up or thumbs-down a sample, and the app reports how many thumbs-ups each mode (classical only versus with the smart pass) would have kept and how many thumbs-downs it would wrongly keep. Add an evaluation view where about 50 user-labeled frames are run through Haiku 5.5 and Sonnet 5.5 and agreement is reported.
Models are not bundled. Download each on first use with a progress bar and checksum verification, store them in app data, work offline afterward, and degrade gracefully with a clear message if a model is missing.
